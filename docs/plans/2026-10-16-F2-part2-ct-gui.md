# F2 part 2: calibration transfer GUI — validate/compare, ID pairing, groups, joins

Branch `zcode/f2-part2-gui`. Follows F2 part 1 (PR #97) and part 1b (PR #98): the backend
(`transfer_evaluation`, physical match, grouped scoring, diagnostics) is on `main`; this PR wires it
into the Calibration Transfer tab (tab10) of `spectral_predict_gui_optimized.py` (~64k lines; CT
code ~48300-53500 methods, ~56200-57100 widgets). Only names on the AGENT_COMPOSITION declared
surface, plus `sample_selection.kennard_stone`/`spxy`, which this PR declares (the GUI already
imports `kennard_stone` undeclared at ~50834).

  `(wavelengths, X)` in `current_primary_data`/`current_satellite_data`; the directory helper

  `ct_transfer_model` + `current_transfer_model`, enables `ct_save_tm_button`, calls

  A2 (configure method) → B) application mode → Mode A (C1-C3 predict) / Mode B (export).

## 1. UI layout

New LabelFrame **"A1b) Validate & Compare Transfer Methods"** inside `ct_build_new_frame`, packed
between the A1 data section and the A2 method section (~56403). Rows, top to bottom:

1. **Pairs**: "Pairs table (optional, CSV): [entry][Browse][Load]", accent button
   **"Pair by Sample ID"**, status label ("40 pairs matched · 2 primary-only · 1 satellite-only").
2. **Pairs Treeview** (height 6, scrollbar): columns `Primary | Satellite | Group`. Matched pairs
   first; below them the unmatched IDs with "(no match)" in the other column and a grey tag.
   Under it: group Entry + button "Set group on selected rows" (writes the Group column of the
   selection; this is how groups are given without a pairs table).
3. **Model (optional)**: "Prediction model (.dasp): [entry][Browse][Load]" + status label showing
   model name, task type and wavelength range. Loaded with the existing `_load_model_file_for_ct`
   (~48259) into `ct_eval_model_dict` (separate from Mode A's C1 model).
4. **Options**: "Space: [Reflectance|Absorbance]" (default = detected type of the primary;
   mismatched primary/satellite types are refused with a pointer to the existing Convert buttons);
   "Detector joins: [Auto (detect from spectra) | ASD file header | None | Custom]" + a Custom
   entry ("e.g. 1000, 1800"); after a run a label reports "Joins used: 1000, 1800 nm (source:
   detected|header|user|none)".
5. **Run**: accent button "Validate & Compare" (disabled while running, shows "Running…" in the
   status label), then:
6. **Leaderboard Treeview** (scrollbar): Label, RMSD_vs_primary, Slope_vs_primary,
   RMSD_vs_primary_grouped, Slope_vs_primary_grouped, RMSEP(_grouped), spectral_RMSE(_grouped),
   improvement — only the columns the board actually has; header line "Ranked by
   \<score_column\> · n candidates". The unranked "Primary instrument (reference)" row stays last
   with a grey tag. Row click or double-click selects a candidate.
7. **Warnings & diagnostics Text** (height 6): `ev.warnings`, joins + source, noisy regions per
   instrument, satellite-much-noisier regions, noise ratio.
8. **"Fit Selected Method"** (accent) and **"Plan Transfer Standards…"** buttons.

"Plan Transfer Standards…" opens a Toplevel: source radio (loaded primary spectra / loaded
satellite spectra / browse a folder), "How many standards" entry (default 15), Run, result
Treeview (order of selection: sample IDs), "Export CSV" (columns `index, sample_id`), Close. Runs
`kennard_stone` in the worker thread (the distance matrix on a big folder is seconds-to-minutes).

## 2. Data flow (backend calls, with arguments)

**Loaders keep IDs (commit 1).** `_load_spectra_from_directory` additionally records
`self._last_dir_ids = list(df.index)`; the A1 loaders store `current_primary_df` /
`current_satellite_df` (DataFrames, index = sample IDs, columns = wavelengths) beside the existing
arrays. Single-file CSV/NPY loads have no IDs → positional IDs `row_0…row_n` and the pairing
report says "no sample IDs in this source; positional order". `_load_spectra_from_directory_as_df`
(~50071) is not reused (it re-detects; the A1 loaders already have the flow).

**Pairing (commit 1).** `_pair_ct_standards()` builds the two DataFrames (applying the pairs
table if loaded), calls
`pair_standards_by_id(primary_df, satellite_df)` → `self.ct_paired` (`PairedStandards`:
`X_primary, X_satellite, ids, satellite_ids, wavelengths, unmatched_primary, unmatched_satellite`).
Pairs-table CSV (`tools/transfer_pairs_benchmark.py` format): columns `primary`, `satellite`,
optional `group`; stems matched case/space-insensitively; the satellite index is renamed to the
primary ID so `pair_standards_by_id` sees identical IDs; the `group` column seeds the Treeview's
Group column; table rows naming a file not present in the loaded folders are reported. Unmatched
IDs are listed in the Treeview and status label, never silently dropped. Duplicate IDs / < 2
matches / grids differing beyond tolerance raise through to a `messagebox.showerror` carrying the
backend message (different grids = CT5, the message says so).
`_build_transfer_model_new` now calls `_pair_ct_standards()` and works on
`ct_paired.X_primary/X_satellite/wavelengths`; the silent row-order interpolation (~50719-50735)
is removed. Primary row order is preserved, so TSR indices etc. keep their meaning.

**Validate run (commit 2).** On the main thread, freeze every input into plain arguments (no Tk
reads in the worker): `Xp, Xs = ct_paired.X_primary, ct_paired.X_satellite`;
`wavelengths = ct_paired.wavelengths`; `space` from the combobox (must equal both detected types);
`joins` resolved now: Auto → `'auto'`, ASD header → the `detector_joins` tuple captured at load
time from each instrument's `_last_dir_load_metadata` (primary's, else satellite's; provenance
label "header"), None → `None`, Custom → parsed floats (provenance "user"); `groups` from the
Treeview (None when the column is empty); `predict = predict_fn_from_model(ct_eval_model_dict,
wavelengths)` and `model_wavelengths = model metadata['wavelengths']` when a model is loaded
(non-regression models: `predict_fn_from_model` raises NotImplementedError — caught and shown).
Percent reflectance: if `space == 'reflectance'` and an instrument's
`ct_*_reflectance_scale == 100`, divide that instrument's array by 100 before the call and
note it in the diagnostics text (physical match refuses values > 1.5). Worker calls

```python
evaluate_transfer(Xp, Xs, predict=predict, ids=ct_paired.ids, groups=groups,
                  wavelengths=wavelengths, space=space, joins=joins,
                  model_wavelengths=model_wavelengths)
```

`wavelengths` + `space` together turn on the physical-match candidates (the GUI never calls
`default_transfer_candidates` itself). No `y` in this PR → no RMSEP/prediction-correction rows;
the board ranks by `RMSD_vs_primary` (model) or `spectral_RMSE`. Result stored as
`self.ct_last_evaluation`; the after-callback populates the leaderboard, warnings and diagnostics.

**Fit selected (commit 2).** Worker calls
`fit_transfer(candidate, Xp, Xs, wavelengths=, space=, joins=, primary_id=<primary folder name>,
satellite_id=<satellite folder name>)` where `candidate = ev.candidates[selected label]`.
`TransferModel` result → assign `ct_transfer_model` + `current_transfer_model`, set
`ct_X_primary_common/ct_X_satellite_common/ct_wavelengths_common` from the paired arrays, update
`ct_transfer_info_text` (label, method, n standards, physical-match `params['notes']` when
present), enable `ct_save_tm_button`, `_update_active_transfer_model_status()`,
`_plot_transfer_quality(method)` — i.e. the existing save/apply paths, unchanged. `None`
("No correction") → info text says so, save stays disabled. A prediction-correction dict cannot
occur without y, but is handled defensively (shown in the info text, not assigned).

## 3. Threading

The 33400-33462 pattern, not a new one: an `self._ct_validate_running` flag guards double
launches; Run/Fit/Plan buttons are disabled and the status label says "Running…" before
`threading.Thread(target=_worker, daemon=True).start()`; the worker never touches Tk — it takes
frozen plain arguments and returns `(ok, payload_or_error_text)`; the completion handler
(`_on_ct_validate_done`) is a separate main-thread method the tests can call directly, invoked via
`self.root.after(0, ...)`. Every exception in the worker is caught and reported through that
handler with a `messagebox.showerror` on the main thread. (Not a Bayesian launch:
`_confirm_resume_before_launch`, `BAYESIAN_REQUIRED_SETTINGS` and `CAPTURABLE_SETTINGS` are
untouched.)

## 4. Errors and messages

- Pairing failures (duplicates, < 2 matches, grid mismatch): showerror with the backend message;
  the Treeview still lists what matched and what did not.
- Unmatched IDs: never dropped silently — status label counts them, Treeview lists them; a
  warning row appears in the diagnostics text after a run.
- Primary/satellite type mismatch or space ≠ detected types: refuse, point at the Convert buttons.
- Non-regression model for `predict`: "prediction scoring needs a regression model; spectral
  scores still work if you clear the model".
- No paired standards / no model where needed: disabled buttons plus a status-label hint, not
  dialogs on every click.
- `ev.warnings` (grouped-vs-LOSO, noisy regions, satellite-noisier-on-model-wavelengths) go into
  the diagnostics text verbatim.

## 5. What is persisted

Nothing new across sessions: the CT tab has no settings persistence today and the validate inputs
are not analysis/Bayesian inputs. Session state (`ct_paired`, group map, header joins per
instrument, `ct_last_evaluation`, `ct_eval_model_dict`) is reset when either loader runs. Saved
`.json/.npz` transfer files via the existing `_save_ct_transfer_model` carry the fit metadata
(including physical-match `meta['notes']`), which is the durable artifact.

## Open questions

1. **Reference y for RMSEP columns?** Not in this PR (recommended): without y the board still
   ranks by `RMSD_vs_primary`, which part 1 established as the right rank column; y would need a
   per-standard reference source (pairs-table `y` column is the natural carrier — part 3, with
   the `.dasp` adapters). Say the word and a "reference values" pair-table column rides along.
2. **Removing the silent satellite→primary interpolation in `_build_transfer_model_new`**
   (recommended): after this PR both grids must already match within `wavelength_matching`
   tolerance, else pairing refuses with an explanation (grid intersection is CT5). This is the
   sanctioned backend behavior; the old interpolation silently paired by row order, which is the
   bug being fixed. Keep the old interpolation as a fallback instead?
3. **Plan-standards v1 scope** (recommended as planned): Kennard-Stone only, on the loaded A1
   spectra or a browsed folder, export CSV; SPXY (y-aware) waits for y support (Q1). Wider
   (duplex, compare methods) is out.
4. **Groups without a pairs table**: the "Set group on selected rows" Treeview editing (planned)
   vs a free-text "id=group" mapping field. The Treeview is more clicks but shows exactly what
   will be sent; recommended.
