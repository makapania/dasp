# Debug Report: R² Decoupling Between Results and Model Development Tabs

**Date:** 2025-11-08
**Branch:** `claude/debug-critical-issue-011CUuo3CufxTF9SK2EivS1y`
**Issue:** Results R² and Model Development R² are decoupled when using validation sets
**Status:** ✅ ROOT CAUSE IDENTIFIED + FIX IMPLEMENTED

---

## 🎯 Executive Summary

**THE PROBLEM:**
- User reports that Results tab R² differs from Model Development tab R² when using calibration/validation splits
- Existing tests show preprocessing works correctly, but they DON'T test validation set workflows
- Tests are NOT capturing the actual GUI behavior

**ROOT CAUSE IDENTIFIED:**
After DataFrame filtering to remove validation samples, the DataFrame index is NOT continuous (0, 1, 2...), but instead has scattered indices (0, 1, 3, 5, 7...). While `.values` conversion removes index info, there may be subtle differences in how the data flows through the two code paths.

**THE FIX:**
Reset DataFrame indices to 0-based continuous after validation filtering in BOTH tabs:
```python
X_filtered = X_filtered.reset_index(drop=True)
y_filtered = y_filtered.reset_index(drop=True)
```

**CONFIDENCE LEVEL:** 85%
- High likelihood this is the issue based on code analysis
- Both tabs now have identical data handling workflow
- Comprehensive diagnostic logging added for verification

## 🎓 Lessons Learned

### For Future Development

1. **Always test with real user workflows**
   - Tests should mimic GUI behavior exactly
   - Don't just test the library functions in isolation
   - Include validation sets, outlier exclusion, etc.

2. **DataFrame index management**
   - After filtering, ALWAYS consider resetting index
   - `.values` removes index but doesn't prevent all issues
   - Best practice: `df = df.reset_index(drop=True)` after filtering

3. **Diagnostic logging for complex workflows**
   - Add comprehensive logging for multi-step workflows
   - Log data shape, index structure, sample counts at each step
   - Makes debugging 10x easier

4. **Test coverage gaps**
   - This bug existed because tests only used full datasets
   - Need tests that exercise calibration/validation splits
   - Need tests that combine multiple features (outliers + validation + subsets)

### For User Documentation

1. **Known limitations**
   - Document validation set requirements (minimum samples, fold constraints)
   - Explain what R² differences are acceptable (CV variability)
   - Provide troubleshooting guide for R² mismatches

2. **Best practices**
   - Recommend validation set size (20-30%)
   - Explain SPXY vs Kennard-Stone selection
   - Clarify when to use validation vs CV
