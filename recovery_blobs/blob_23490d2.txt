# Manual Testing Guide for Model Loading Engine

## Prerequisites

1. Ensure you have run an analysis that generates results with the `all_vars` field
2. Have the GUI running with data loaded
3. Have results displayed in the Results tab (Tab 5)

## Test Scenarios

### Test 1: Load PLS Model with top50 Subset

**Steps:**
1. Run analysis with:
   - Models: PLS
   - Subsets: top50
   - Preprocessing: snv, sg1
2. Navigate to Results tab
3. Double-click on Rank 1 result

**Expected Output (Console):**
```
================================================================================

================================================================================
  Model: PLS
  Performance: [R² value]
  Variables: 50
  Loading into Custom Model Development tab...

================================================================================
LOADING MODEL INTO CUSTOM MODEL DEVELOPMENT TAB
================================================================================

[STEP 1/7] Validating data availability...
✓ Data validation passed: X, y, and wavelengths are available
  - X shape: [shape]
  - y length: [length]
  - Available wavelengths: [count]

[STEP 2/7] Building configuration information display...
✓ Configuration text built: PLS, 50 wavelengths

[STEP 3/7] Loading wavelengths with strict validation...
⚠️  CRITICAL SECTION: FAIL LOUD validation - no silent fallbacks!
  Subset model detected: 'top50' with 50 variables
  Parsing 'all_vars' field...
  ✓ Parsed 50 wavelengths from 'all_vars'
  ✓ Validation passed: All 50 wavelengths are valid
✓ Wavelength loading complete: 50 wavelengths validated

[STEP 4/7] Formatting wavelengths for display...
✓ Formatted 50 wavelengths ([n] characters)
✓ Wavelength widget updated: [n] characters inserted

[STEP 5/7] Loading hyperparameters...

[STEP 6/7] Populating GUI controls...
  ✓ Model info display updated
  ✓ Model type: PLS
  ✓ Task type: regression (auto-detected)
  ✓ Preprocessing: snv_sg1
  ✓ Window size: 17
  ✓ CV folds: 5 (ensures same CV strategy as Results)

[STEP 7/7] Finalizing...
✓ Mode label updated: Loaded from Results (Rank 1)
✓ Run button enabled

   - 50 wavelengths loaded and validated
   - Preprocessing: snv_sg1
   - Ready for refinement

```

**Expected GUI State:**
- Tab switches to "Custom Model Development" (Tab 6)
- Model info box shows configuration with Rank 1
- Wavelength text box shows 50 wavelengths (comma-separated)
- Model type dropdown: PLS
- Preprocessing dropdown: snv_sg1
- Window size: 17 (or from config)
- CV folds: 5 (or from config)
- Run button: ENABLED (green)
- Mode label: "Mode: Loaded from Results (Rank 1)" in green

**Verify:**
- [ ] All 50 wavelengths are shown (not all 2151)
- [ ] Wavelength count label shows "Wavelengths: 50 selected"
- [ ] No errors in console
- [ ] Run button is clickable

### Test 5: Error Case - Missing all_vars Field (Simulated)

**Note:** This test requires modifying results DataFrame temporarily or using old results.

**Expected Behavior:**
- Error dialog appears:
  ```
  Model Loading Failed - Data Validation Error

  CRITICAL ERROR: Missing 'all_vars' field for subset model!
    Model: [name] (Rank [rank])
    Subset: [tag]
    Expected variables: [n]

  The 'all_vars' field is REQUIRED for subset models to identify
  the exact wavelengths used. Without it, loading this model
  would cause R² discrepancies.

  SOLUTION: Re-run the analysis to generate complete results.
  ```

- Console shows:
  ```
  ❌ VALIDATION ERROR:
  [same message as above]
  [stack trace]
  ```

**Verify:**
- [ ] Error dialog is clear and actionable
- [ ] Console shows full details
- [ ] GUI doesn't crash
- [ ] Tab doesn't switch
- [ ] Can try loading another model

---

### Test 6: Error Case - Wavelength Count Mismatch (Simulated)

**Note:** This would require corrupted results data.

**Expected Behavior:**
- Error dialog appears:
  ```
  Model Loading Failed - Data Validation Error

  CRITICAL ERROR: Wavelength count mismatch!
    Model: [name] (Rank [rank])
    Expected: [n] wavelengths (from n_vars field)
    Parsed: [m] wavelengths (from all_vars field)
    Subset: [tag]

  This indicates a data integrity issue in the results table.
  The 'all_vars' field does not match the 'n_vars' count.

  SOLUTION: Re-run the analysis to generate consistent results.
  ```

**Verify:**
- [ ] Error shows both expected and parsed counts
- [ ] Message identifies data integrity issue
- [ ] Provides actionable solution

---

### Test 7: Load Multiple Models in Sequence

**Steps:**
1. Double-click Rank 1 (e.g., PLS)
2. Verify loading
3. Click back to Results tab
4. Double-click Rank 2 (e.g., Ridge)
5. Verify loading
6. Repeat for Ranks 3-5

**Expected Behavior:**
- Each model loads successfully
- Previous model data is completely replaced
- No residual data from previous loads
- Mode label updates with current rank each time

**Verify:**
- [ ] Each model loads independently
- [ ] No data mixing between models
- [ ] Console logging clear for each load
- [ ] Memory doesn't grow excessively

---

### Test 9: Load with Various Preprocessing Methods

**Test each preprocessing method:**
- raw → raw
- snv → snv
- deriv (order=1) → sg1
- deriv (order=2) → sg2
- snv_deriv (order=1) → snv_sg1
- snv_deriv (order=2) → snv_sg2
- deriv_snv → deriv_snv
- msc → msc
- msc_deriv (order=1) → msc_sg1
- msc_deriv (order=2) → msc_sg2
- deriv_msc → deriv_msc

**Expected Behavior:**
- Each backend naming converts to correct GUI naming
- Preprocessing dropdown shows correct value
- Window size loaded correctly
- Console shows: "✓ Preprocessing: [gui_name]"

**Verify:**
- [ ] All preprocessing methods convert correctly
- [ ] No "Unknown preprocessing" warnings
- [ ] Window size matches config

**Steps:**

## Edge Cases

### Test E1: Load with No Data

**Steps:**
1. Start fresh GUI (no data loaded)
2. Load old results file (if possible)
3. Try to double-click result

**Expected:**
- Error: "Data validation failed! Required data (X, y, wavelengths) is not available."
- No crash

**Verify:**
- [ ] Clear error message
- [ ] No crash
- [ ] Can load data and retry

---

### Test E2: Load with Different Dataset

**Steps:**
1. Run analysis with Dataset A
2. Load different Dataset B
3. Try to load results from Dataset A

**Expected:**
- For subset models: May get "Invalid wavelengths" error if wavelengths don't match
- For full models: May get warning if count doesn't match
- Clear error message in either case

**Verify:**
- [ ] Detects dataset mismatch
- [ ] Error message is clear
- [ ] Suggests solution

---

## Acceptance Criteria

All tests pass when:
- [ ] No silent fallbacks to all wavelengths for subset models
- [ ] All errors have clear, actionable messages
- [ ] Console logging is comprehensive
- [ ] GUI remains stable and responsive
- [ ] All model types load correctly
- [ ] All preprocessing methods convert correctly
- [ ] Performance is acceptable (< 2 seconds)
- [ ] No memory leaks in repeated loads
- [ ] Error cases are handled gracefully

---

## Reporting Issues

If any test fails, report:
1. Test number and name
2. Steps to reproduce
3. Expected behavior
4. Actual behavior
5. Console output (full log)
6. Screenshot of error dialog (if applicable)
7. Dataset characteristics (size, type, etc.)
