# R² Discrepancy Fix Between Results Tab and Model Development Tab

**Date:** November 5, 2025
**Status:** ✅ FIXED - Three critical issues identified and resolved
**Impact:** Model Development tab now reproduces exact R² values from Results tab

---

## Problem Description

When clicking on a model in the Results tab and running it in the Model Development tab, the R² value was **different** from what was shown in Results. This was a regression that occurred after porting the backend to Julia, similar to an issue that was previously fixed in the Python implementation.

---

## Root Causes Identified

### Issue #1: Number of CV Folds Not Preserved ❌
**Problem:** The number of cross-validation folds used during the main search was not being stored in the results DataFrame.

**Impact:** Model Development tab always used the default (5 folds), even if Results used a different number (e.g., 3, 7, or 10 folds).

**Files Affected:**
- `julia_port/SpectralPredict/src/search.jl:856` (Julia backend)
- `spectral_predict_gui_optimized.py:3264-3268` (Python GUI)

---

### Issue #2: Different Fold Splitting Algorithms ❌
**Problem:** Julia and Python use different random number generators:
- **Julia:** Uses `Random.randperm()` with seed 42
- **Python:** Uses `sklearn.KFold(shuffle=True, random_state=42)`

Even with the same seed, these produce **different fold splits** because they use different RNG algorithms.

**Impact:** Cross-validation was using completely different train/test splits, leading to different R² values.

**Files Affected:**
- `julia_port/SpectralPredict/src/cv.jl:102-106` (Julia fold creation)
- `spectral_predict_gui_optimized.py:3919-3927` (Python Model Development CV)

---

### Issue #3: Wavelength Specification Not Stored ❌ **CRITICAL**
**Problem:** Julia backend stored variable selection as **indices** (`VarSelectionIndices`) but did not store the actual **wavelength values** that Python GUI expects in the `all_vars` field.

**Impact:** When loading a subset model:
- Python GUI could not find wavelength values in `all_vars` or `top_vars`
- **Fell back to using ALL wavelengths** instead of the selected subset
- This caused completely wrong model specifications, leading to different R² values

**Files Affected:**
- `julia_port/SpectralPredict/src/search.jl:791-891` (Julia search function)
- `spectral_predict_gui_optimized.py:3180-3217` (Python wavelength loading)

---

### Fix #2: Deterministic Fold Splitting ✅

**Julia Backend (`cv.jl:102-106`):**
```julia
# CRITICAL FIX: Use sequential indices instead of shuffling to ensure
# identical fold splits between Julia and Python backends
# This is necessary because Julia's randperm() and sklearn's KFold use
# different RNG algorithms, creating different splits even with same seed
shuffled_indices = collect(1:n_samples)  # Sequential order (no shuffle)
```

**Python GUI (`spectral_predict_gui_optimized.py:3919-3927`):**
```python
# Prepare cross-validation
# CRITICAL FIX: Use shuffle=False to ensure identical fold splits as Julia backend
# Julia and Python use different RNG algorithms, so even with same seed (42),
# they create different splits when shuffle=True. Using shuffle=False ensures
# deterministic, data-order-based folds that match between backends.
y_array = y_series.values
if task_type == "regression":
    cv = KFold(n_splits=n_folds, shuffle=False)  # No shuffle for consistency
else:
    cv = StratifiedKFold(n_splits=n_folds, shuffle=False)  # No shuffle for consistency
```

**Why This Works:**
- Both Julia and Python now create folds based on **data order** (sequential indices)
- No randomness = perfect consistency between backends
- First fold always gets samples [1, 2, ..., n/k], second fold gets [n/k+1, ..., 2n/k], etc.

### Fix #3: Store Actual Wavelength Values ✅

**Julia Backend (`search.jl:805, 876-891`):**

1. **Added wavelengths parameter to `run_single_config`:**
```julia
function run_single_config(
    # ... existing parameters ...
    wavelengths::Union{Vector{Float64},Nothing}=nothing  # CRITICAL FIX: wavelengths for storing actual values
)::Union{Dict{String, Any}, Nothing}
```

2. **Convert indices to wavelength values and store:**
```julia
# CRITICAL FIX: Store actual wavelength values for Python GUI
# Python GUI expects "all_vars" to contain actual wavelengths, not indices
if !isnothing(wavelengths)
    if !isnothing(var_selection_indices)
        # Subset model: store only selected wavelengths
        selected_wavelengths = wavelengths[var_selection_indices]
        result["all_vars"] = join([string(wl) for wl in selected_wavelengths], ", ")
    elseif subset_tag == "full"
        # Full model: store all wavelengths
        result["all_vars"] = join([string(wl) for wl in wavelengths], ", ")
    else
        result["all_vars"] = "N/A"
    end
else
    result["all_vars"] = "N/A"
end
```

3. **Updated all `run_single_config` calls to pass wavelengths:**
```julia
# Full models
result_full = run_single_config(
    X, y, model_name, config, preprocess_cfg, task_type, n_folds,
    # ... other params ...
    wavelengths=wavelengths  # Pass wavelengths for storing actual values
)

# Variable subset models
result = run_single_config(
    X_preprocessed[:, selected_indices], y,
    model_name, config, preprocess_cfg, task_type, n_folds,
    # ... other params ...
    var_selection_indices=selected_indices,
    wavelengths=wavelengths  # Pass wavelengths for storing actual values
)

# Region subset models
result = run_single_config(
    X_preprocessed[:, region["indices"]], y,
    model_name, config, preprocess_cfg, task_type, n_folds,
    # ... other params ...
    var_selection_indices=region["indices"],
    wavelengths=wavelengths  # Pass wavelengths for storing actual values
)
```
