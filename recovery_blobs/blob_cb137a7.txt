**Complete UI sections:**

#### Header Section
- Mode indicator label (shows "Fresh Development" or "Loaded from Results")
- Reset button with confirmation dialog
- Configuration info text widget (5 lines, read-only) showing loaded model metadata

#### Parameter Controls (2-Column Layout)

**Left Column - Core Parameters:**
- Model Type dropdown: PLS, Ridge, Lasso, RandomForest, MLP, NeuralBoosted
- Task Type dropdown: regression, classification
- Backend dropdown: python (Julia support ready but keeping simple)
- Preprocessing dropdown: 11 methods (raw, snv, sg1, sg2, snv_sg1, snv_sg2, deriv_snv, msc, msc_sg1, msc_sg2, deriv_msc)

  - "All" - loads all wavelengths from data
  - "NIR (1000-2500)" - NIR range
  - "Visible (400-700)" - visible spectrum
  - "Custom Range..." - opens dialog for user input
- Real-time wavelength count label
- Dynamic hyperparameter frame (changes based on model type)

#### Dynamic Hyperparameters (per model type)

| Model | Parameters |
|-------|------------|
| **PLS** | n_components (1-50, spinbox) |
| **Ridge/Lasso** | alpha (float entry) |

| **MLP** | hidden_layer_sizes (tuple entry), learning_rate_init (float entry) |
| **NeuralBoosted** | n_estimators (10-200), learning_rate (float), hidden_layer_size (3-20) |

#### Results Display
- 8-line read-only text widget with monospace font
- Shows R², RMSE, MAE, fold-by-fold results
- Initialized with helpful placeholder text

#### Diagnostic Plots (3 side-by-side frames)
- **Plot 1:** Prediction plot (Observed vs Predicted)
- **Plot 2:** Residual diagnostics
- **Plot 3:** Model comparison (multiple runs)
- Each plot: 300x250 pixels with placeholder labels
- Stored as `self.tab7_plot1_frame`, `self.tab7_plot2_frame`, `self.tab7_plot3_frame`

#### Status Label
- Bottom status bar for real-time updates
- Updates during user actions (preset selected, model type changed, etc.)

## Design Decisions

### Why 2-Column Layout?
- Logical grouping: core params vs wavelengths/hyperparams
- Efficient use of horizontal space
- Easy to scan and understand

### Why Dynamic Hyperparameters?
- Each model has different parameters
- Avoids clutter of showing all parameters at once
- User sees only relevant controls

### Why Real-Time Wavelength Count?
- Immediate feedback on input
- Helps catch errors (typos, invalid ranges)
- Professional feel

### Why Preset Buttons?
- Common use cases made easy
- Reduces manual typing
- Guides new users

### Why Placeholder Plots?
- Shows where plots will appear
- Helps with layout during development
- Clear messaging about future functionality

### Why Reset Confirmation?
- Prevents accidental data loss
- Professional UX pattern
- Gives user chance to cancel
