## Issue #1: Wavelength Specification Wrong ❌ **CRITICAL**

### Problem
- Julia stored variable indices but not actual wavelength values
- Python GUI expected wavelengths in `all_vars` field
- When loading subset models (e.g., top 50 variables), GUI couldn't find wavelengths
- **Fell back to using ALL wavelengths** instead of selected subset
- This meant completely different model → R² difference of 0.1-0.3+

### Your Key Insight
> "I think the problem is because when I select a model in results the wavelength specification is wrong"

**You were absolutely right!** This was the biggest issue.

### Fix Applied
**Julia Backend (`search.jl:805, 876-891`):**
```julia
# Added wavelengths parameter to run_single_config
function run_single_config(
    # ... existing parameters ...
    wavelengths::Union{Vector{Float64},Nothing}=nothing  # NEW
)

# Store actual wavelength values
if !isnothing(wavelengths)
    if !isnothing(var_selection_indices)
        # Subset model: store only selected wavelengths
        selected_wavelengths = wavelengths[var_selection_indices]
        result["all_vars"] = join([string(wl) for wl in selected_wavelengths], ", ")
    elseif subset_tag == "full"
        # Full model: store all wavelengths
        result["all_vars"] = join([string(wl) for wl in wavelengths], ", ")
    end
end
```

**Impact:** Now stores "400.0, 402.0, 404.0, ..." instead of just indices

## Issue #2: Hyperparameters Not Being Loaded ❌ **CRITICAL**

### Problem
- Julia stores hyperparameters as individual fields:
  - `result["alpha"] = 0.1` (Ridge/Lasso)
  - `result["n_trees"] = 100` (RandomForest)
  - `result["learning_rate"] = 0.05` (NeuralBoosted)
- Python GUI looked for them in a `Params` field that doesn't exist!
- Result: Model Development used **default** hyperparameters instead of tuned ones

### Symptoms You Reported
> "For ridge, the selected model and what was produced on model development were not related"
- Results used tuned alpha=0.1
- Model Development used default alpha=1.0
- Completely different regularization → very different model

> "For random forest, the model development was higher than the initial result"
- Results used tuned n_trees=50, max_features='sqrt'
- Model Development used default n_trees=100, max_features='auto'
- More trees → higher R² (overfitting during CV)

### Fix Applied
**Python GUI (`spectral_predict_gui_optimized.py:3895-3938`):**
```python
# CRITICAL FIX: Reapply tuned hyperparameters from the search results
# Julia backend stores hyperparameters as individual fields (alpha, n_trees, etc.)
# NOT in a 'Params' string field like old Python implementation
params_from_search = {}
if self.selected_model_config is not None:
    # Extract hyperparameters based on model type
    if model_name == 'Ridge' or model_name == 'Lasso':
        if 'alpha' in self.selected_model_config:
            params_from_search['alpha'] = float(self.selected_model_config['alpha'])
            print(f"DEBUG: Loaded alpha={params_from_search['alpha']} for {model_name}")

    elif model_name == 'RandomForest':
        if 'n_trees' in self.selected_model_config:
            # Julia uses n_trees, scikit-learn uses n_estimators
            params_from_search['n_estimators'] = int(self.selected_model_config['n_trees'])
        if 'max_features' in self.selected_model_config:
            params_from_search['max_features'] = str(self.selected_model_config['max_features'])

    # Similar for MLP, NeuralBoosted...

if params_from_search:
    model.set_params(**params_from_search)
    print(f"DEBUG: ✓ Applied tuned hyperparameters: {params_from_search}")
```

**Impact:** Now loads exact hyperparameters from Results tab

## Issue #4: Different Fold Splitting Algorithms ❌

### Problem
- Julia's `Random.randperm(42)` creates different splits than Python's `KFold(random_state=42)`
- Even with same seed, different RNG algorithms → different train/test splits
- Different splits → different R² values

### Fix Applied
**Both backends now use deterministic, sequential fold splitting (NO shuffle):**

**Julia (`cv.jl:102-106`):**
```julia
# CRITICAL FIX: Use sequential indices instead of shuffling
shuffled_indices = collect(1:n_samples)  # No shuffle
```

**Python (`spectral_predict_gui_optimized.py:3924-3927`):**
```python
# CRITICAL FIX: Use shuffle=False for identical fold splits
if task_type == "regression":
    cv = KFold(n_splits=n_folds, shuffle=False)  # No shuffle
else:
    cv = StratifiedKFold(n_splits=n_folds, shuffle=False)
```

**Why This Works:** Both backends now create identical fold splits based on data order

## Issue #5: Preprocessing Order Unclear ⚠️ (UX Issue)

### Problem You Reported
> "How do you tell the order in which things were applied? For instance, where the model is derivative2 then snv"

- Results showed `Preprocess: deriv_snv, Deriv: 2`
- Not obvious this means "2nd derivative THEN SNV"
- Could be confused with "SNV THEN 2nd derivative"

### Fix Applied
**Python GUI (`spectral_predict_gui_optimized.py:2945-2980`):**

Now displays preprocessing with arrow notation showing order:
- `deriv_snv` + `Deriv=2` → displays as **`Deriv2→SNV`**
- `snv_deriv` + `Deriv=1` → displays as **`SNV→Deriv1`**
- `msc_deriv` + `Deriv=2` → displays as **`MSC→Deriv2`**
- `deriv_msc` + `Deriv=1` → displays as **`Deriv1→MSC`**

The arrow (→) makes it crystal clear what happens first!

## Root Cause Analysis

### Why These Bugs Happened

1. **Wavelength Issue:** Julia stores data efficiently (indices), Python GUI expected user-friendly format (values). Mismatch in expectations.

2. **Hyperparameter Issue:** Julia uses dictionary unpacking (stores `alpha`, `n_trees` directly), old Python used serialized `Params` string. Interface change not caught.

3. **Fold Count Issue:** Easy to forget to store "meta" parameters that affect CV strategy.

4. **Fold Splitting Issue:** Different languages, different RNG implementations. Should have used deterministic approach from start.

5. **Preprocessing Display Issue:** Code-friendly names (`deriv_snv`) aren't user-friendly. Needed better UX.

### Prevention Strategies

1. **Always store complete configuration** - Everything needed to reproduce results
2. **Test cross-language interfaces carefully** - Different data representations
3. **Use deterministic algorithms** when reproducibility matters
4. **Design for humans** - Display names should be clear, not just technically correct
