## Project Overview

**Spectral Predict** is an automated spectral analysis software for preprocessing, modeling, and ranking spectroscopy data. It provides both a GUI application and a command-line interface for building and evaluating spectral models.

**Repository name:** dasp (Spectral Predict)
**Language:** Python ≥ 3.10
**Main application:** GUI-based spectral analysis tool with automated model search

## Development Commands

### Running the Application

```bash
# Run the GUI (production version)
python spectral_predict_gui_optimized.py

# Run CLI (after pip install -e .)
spectral-predict --spectra data.csv --reference ref.csv --id-column sample_id --target nitrogen

# Run CLI with ASD files
spectral-predict --asd-dir example/ --reference example/BoneCollagen.csv --id-column "File Number" --target "%Collagen"
```

## Architecture

### Core Library Structure (`src/spectral_predict/`)

The codebase follows a modular architecture with clear separation of concerns:

**Data Flow Pipeline:**
```
Input Data → Preprocessing → Model Search → Cross-Validation → Ranking → Output
```

**Key Modules:**

- **`search.py`** (main engine): Orchestrates the entire model search process
  - `run_search()`: Main entry point for automated model testing
  - Handles preprocessing × model × hyperparameter grid search
  - Implements parallel CV using joblib
  - Supports multiple variable selection methods
  - Progress callback system for GUI integration

- **`preprocess.py`**: Spectral preprocessing transformers
  - sklearn-compatible transformers: `SNV`, `SavgolDerivative`
  - `build_preprocessing_pipeline()`: Creates preprocessing pipelines
  - Supports: raw, SNV, derivatives (1st/2nd), SNV+deriv, deriv+SNV
  - Pipeline order matters: "deriv_snv" means derivative THEN SNV

- **`models.py`**: Model definitions and grid configurations
  - `get_model()`: Factory function for model instances
  - `get_model_grids()`: Hyperparameter grids for each model
  - `get_feature_importances()`: Extract model-specific importance scores (VIP, coefficients, feature_importances_)
  - Models: PLS, Ridge, Lasso, RandomForest, MLP, NeuralBoosted, PLS-DA

- **`model_io.py`**: Model persistence (.dasp format)
  - `save_model()`: Saves model + metadata + preprocessing pipeline
  - `load_model()`: Restores complete model configuration
  - **Critical**: Tracks preprocessing mode (full-spectrum vs subset) to handle derivative+subset edge cases

- **`variable_selection.py`**: 5 variable selection algorithms (~760 lines)
  - `importance_selection()`: Model-specific importance scores (VIP, coefficients, etc.)
  - `spa_selection()`: Successive Projections Algorithm (reduces collinearity)
  - `uve_selection()`: Uninformative Variable Elimination (filters noise)
  - `uve_spa_selection()`: Hybrid approach (UVE then SPA)
  - `ipls_selection()`: Interval PLS (region-based selection)

- **`neural_boosted.py`**: Custom gradient boosting with neural networks
  - `NeuralBoostedRegressor`: sklearn-compatible gradient boosting
  - Uses small neural networks as weak learners
  - Provides interpretable feature importances
  - Supports Huber loss for outlier robustness

- **`outlier_detection.py`**: Sample outlier detection
  - Leverage-based detection (Mahalanobis distance)
  - Residual-based detection (model prediction errors)
  - Combined detection (both criteria)

- **`io.py`**: Data loading (CSV, ASD files)
  - `read_csv_spectra()`: Wide/long format CSV
  - `read_asd_spectra()`: ASCII/binary ASD files
  - `align_xy()`: Flexible ID matching between spectra and reference data

- **`regions.py`**: Spectral region subset analysis
- **`scoring.py`**: Composite score ranking (balances performance + simplicity)
- **`report.py`**: Markdown report generation
- **`cli.py`**: Command-line interface entry point

### GUI Application (`spectral_predict_gui_optimized.py`)

Production-ready GUI (~220KB, ~5000 lines) with 7 tabs:
1. **Import & Preview**: Load spectral data, outlier detection
2. **Absorbance Conversion**: Convert reflectance → absorbance
3. **Analysis Configuration**: Configure models, preprocessing, variable selection
4. **Analysis Progress**: Monitor search progress
5. **Results**: View ranked models (sortable table)
6. **Model Development**: Refine individual models with custom parameters
7. **Model Prediction**: Load saved models, predict on new data

**Important GUI Implementation Details:**
- Uses tkinter with threaded execution to prevent UI freezing
- Progress updates via callback system
- Results table supports column sorting (click headers)
- Model Development tab must exclude validation samples during CV (fixed in commit 559b1fe)
- Handles both full-spectrum and derivative+subset preprocessing modes

### Preprocessing Pipeline Architecture

**Critical Design Pattern:**
The preprocessing pipeline order affects results. There are 5 modes:
- `raw`: No preprocessing
- `snv`: Standard Normal Variate only
- `deriv`: Savitzky-Golay derivative only (1st or 2nd order)
- `snv_deriv`: SNV THEN derivative
- `deriv_snv`: Derivative THEN SNV

**Why this matters:**
1. When saving/loading models, the preprocessing mode must be preserved
2. When applying variable subsetting + derivatives, the subset must be applied AFTER preprocessing
3. The `model_io.py` tracks `preprocess_applied_to` to handle edge cases (see commit 872e816)

### Variable Selection Architecture

The system supports **multiple simultaneous variable selection methods**:
1. User can select multiple checkboxes in GUI (Tab 3)
2. `search.py` loops over each selected method
3. Results are tagged with method name (e.g., "top50_spa", "top50_uve")
4. Users can compare methods side-by-side in Results tab

**Implementation pattern:**
```python
# In search.py
for varsel_method in selected_methods:
    if varsel_method == 'importance':
        selected_indices = importance_selection(...)
    elif varsel_method == 'spa':
        selected_indices = spa_selection(...)
    # ... etc
```

## Critical Bug Fixes (Context for Future Work)

### Fix #1: deriv_snv Preprocessing Mismatch (commit cadc53e)
**Problem:** Model Development tab always used 1st derivative for `deriv_snv`, even when Results used 2nd derivative
**Solution:** Now reads actual `Deriv` value from loaded config
**Location:** `spectral_predict_gui_optimized.py:3222-3242`

### Fix #2: Model Prediction with Derivative+Subset (commit 872e816)
**Problem:** Models with derivative preprocessing + wavelength subsetting gave nonsense predictions
**Root Cause:** Preprocessing pipeline shape mismatch (expected full spectrum, got subset)
**Solution:** Track `preprocess_applied_to` in model metadata ('full' vs 'subset')
**Location:** `src/spectral_predict/model_io.py`

### Fix #3: Validation Set Exclusion (commit 559b1fe)
**Problem:** Model Development tab didn't exclude validation samples during CV
**Impact:** R² was artificially higher in Model Development vs Results
**Solution:** Added validation sample filtering before CV
**Location:** `spectral_predict_gui_optimized.py:3222-3242`
**Note:** This commit also includes validation UI features and variable selection checkboxes (bundled together)

## Common Workflows

### Adding a New Model Type
1. Add model definition to `src/spectral_predict/models.py` in `get_model()`
2. Add hyperparameter grid to `get_model_grids()`
3. Add feature importance extraction logic to `get_feature_importances()`
4. Add GUI checkbox in `spectral_predict_gui_optimized.py` (Tab 3)
5. Add unit tests in `tests/test_*.py`

### Adding a New Preprocessing Method
1. Create sklearn-compatible transformer in `src/spectral_predict/preprocess.py`
2. Add to `build_preprocessing_pipeline()` switch statement
3. Update `spectral_predict_gui_optimized.py` preprocessing options (Tab 3)
4. Test with derivative+subset edge cases

### Adding a New Variable Selection Method
1. Implement function in `src/spectral_predict/variable_selection.py`
2. Add to `search.py` variable selection loop (lines 394-434)
3. Add GUI checkbox in Tab 3
4. Add unit tests in `tests/test_variable_selection.py`

## Important Conventions

### Model Naming
- Use model name prefixes: "PLS", "Ridge", "Lasso", "RandomForest", "MLP", "NeuralBoosted"
- Append hyperparameters to model name in results (e.g., "PLS(n=10)")

### Preprocessing Tag Format
- Tags: "raw", "snv", "deriv", "snv_deriv", "deriv_snv"
- Always include derivative order and window in metadata when applicable

### Result Tagging Convention
- Subset tags: "all", "top{N}_{method}" (e.g., "top50_spa", "top20_importance")
- Region tags: "all", "region_top{N}" (e.g., "region_top5")

### File Extensions
- Model files: `.dasp` (custom format with pickle + JSON metadata)
- Spectral data: `.csv` (wide/long format), `.asd`, `.sig` (ASD files)
- Preprocessed data export: `.csv` with timestamp
