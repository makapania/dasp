## 3 Methods to Integrate

### 1. `_load_model_to_NEW_tab7(config)` - Main Engine

**Purpose:** Loads model from Results tab into Tab 7

**Process:**
1. Validate data availability (X, y, wavelengths)
2. Build configuration info text
3. **CRITICAL:** Load wavelengths with FAIL LOUD validation
4. Format wavelengths for display
5. Load hyperparameters
6. Populate GUI controls
7. Update mode label and status

**Key Behavior:** FAILS LOUD if subset model missing all_vars field

### 2. `_format_wavelengths_for_NEW_tab7(wavelengths_list)` - Helper

**Purpose:** Format wavelength lists for display

**Behavior:**
- Small lists (≤50): Show all wavelengths
- Large lists (>50): Condensed format (first 10 + "..." + last 10)

### 3. `_on_result_double_click_NEW_TAB7(event)` - Handler

**Purpose:** Handle double-click in Results tab

**Behavior:**
- Calls `_load_model_to_NEW_tab7()`
- Switches to Tab 7 (index 6)
- Shows error dialogs for validation failures

## FAIL LOUD Validation Flow

```
Double-click result
     ↓
Is subset model?
     ↓
YES → Check all_vars field
      ├─ Missing? → ❌ CRITICAL ERROR dialog
      ├─ Parse failed? → ❌ CRITICAL ERROR dialog
      ├─ Count mismatch? → ❌ CRITICAL ERROR dialog
      ├─ Invalid wavelengths? → ❌ CRITICAL ERROR dialog
      └─ All valid? → ✓ Load exact wavelengths

NO → ✓ Load all wavelengths
```

**NEVER falls back to full spectrum on error**

## Key Validation Points

### ✓ Must Pass:
- Subset models with valid all_vars load exact wavelengths
- Full spectrum models load all wavelengths
- Config text displays model info correctly
- Hyperparameters populate controls
- Preprocessing names convert correctly

### ✗ Must Fail Loud:
- Subset model missing all_vars field
- Subset model with wavelength count mismatch
- Subset model with invalid wavelengths
- Data not loaded (X, y, wavelengths)
- Malformed all_vars field

### ⚠️ Must NOT Happen:
- Silent fallback to full spectrum
- Partial data loading
- Silently skipping invalid wavelengths
- Loading without validation

## Example Error Message

When validation fails, user sees:

```
CRITICAL ERROR: Missing 'all_vars' field for subset model!
  Model: PLS (Rank 1)
  Subset: top50
  Expected variables: 50

The 'all_vars' field is REQUIRED for subset models to identify
the exact wavelengths used. Without it, loading this model
would cause R² discrepancies.

SOLUTION: Re-run the analysis to generate complete results.
```

**Error messages are:**
- Contextual (show model name, rank, subset)
- Explanatory (why it's a problem)
- Actionable (what to do)

## Troubleshooting

### Problem: "NameError: tab7_wl_spec not defined"

**Cause:** Tab 7 UI not created yet

**Fix:** Create Tab 7 UI controls or test with Tab 6 temporarily

### Problem: Subset model loads full spectrum

**Cause:** Shouldn't happen with this implementation

**Check:** Console logs - should see "CRITICAL SECTION: FAIL LOUD"

### Problem: Error for valid subset model

**Cause:** all_vars field truly missing or malformed

**Fix:** Re-run analysis to regenerate results with all_vars

### Problem: Double-click goes to Tab 6 not Tab 7

**Cause:** Handler not updated

**Fix:** Update binding to use `_on_result_double_click_NEW_TAB7`
